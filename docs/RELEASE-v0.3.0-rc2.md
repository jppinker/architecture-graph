## Boundary

The public repository contains product documentation, a self-contained eShop analysis page, the preserved v0.2.0-rc2 demo, security guidance, a version-specific proprietary evaluation license draft, release notes, and third-party notices. It contains no complete or partial release-source snapshot.

The separately distributed archive necessarily contains inspectable bundled JavaScript. The project does not describe those bytes as secret, and their inspectability does not make the product open source. The archive was not rebuilt or modified during publication preparation.

The eShop demo is derived from [dotnet/eShop](https://github.com/dotnet/eShop) commit `dc7ea499cd356924fb6689b3702964a5869dbae9` under the MIT license. It includes stored project identities, repository-relative paths, line numbers, evidence references, graph data, and impact output; it includes no eShop source excerpts or source files.

## Publication sequence

Publication must not rebuild or modify the frozen archive:

1. Obtain and record every owner/legal approval required by Section 15, including the Publication Date.
2. Review the public PR and confirm the release notes and license presentation remain accurate.
3. Merge the public PR into `main` without changing the frozen demo or version-specific license.
4. Confirm the draft GitHub release still targets `v0.3.0-rc2`, is a prerelease, is not latest, and carries the exact frozen asset digest.
5. Publish the license document and release at the same time. Do not deploy GitHub Pages separately; the existing workflow deploys `demo/` only when the reviewed PR reaches `main`.
6. Download the public asset and verify its SHA-256 again after publication.

Until those actions are explicitly authorized and completed, the GitHub release must remain a draft, the PR must remain unmerged, and no claim that the license is effective should be made.
